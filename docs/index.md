# virtualbox Provider

Interact with a local Oracle VirtualBox installation to manage virtual machines, host-only networks, and shared folders. The provider drives the `VBoxManage` command-line tool, so VirtualBox must be installed on the same host that runs Terraform.

Because the provider shells out to the `VBoxManage` CLI on the machine that runs
Terraform, it is intended for local development and test environments — running a
full hypervisor on the same host as Terraform — rather than remote or multi-host
orchestration.

## Requirements

- [Oracle VirtualBox](https://www.virtualbox.org/wiki/Downloads) 7.x installed on
  the host that runs Terraform, with hardware virtualization (VT-x/AMD-V) enabled.
- The `VBoxManage` command-line tool available on the system `PATH`, or its
  location supplied through the `vboxmanage_path` argument below.

## Example Usage

```terraform
terraform {
  required_providers {
    virtualbox = {
      source  = "bryanjbelanger/virtualbox"
      version = "~> 0.1.0"
    }
  }
}

provider "virtualbox" {
  # Optional: path to VBoxManage (defaults to "VBoxManage" found in PATH).
  # vboxmanage_path = "/usr/local/bin/VBoxManage"
}
```

## Authentication and Configuration

The provider does not use credentials or a remote endpoint; it manages the local
VirtualBox installation directly through `VBoxManage`. The only configuration is
the optional path to that executable.

### Optional

- `vboxmanage_path` (String) Path to the `VBoxManage` executable used to drive VirtualBox. When omitted, the provider looks up `VBoxManage` on the system `PATH`. Set this when VBoxManage is installed in a non-standard location, for example `/usr/local/bin/VBoxManage` on macOS or `C:\Program Files\Oracle\VirtualBox\VBoxManage.exe` on Windows.
